# symphony-protocol

This repository is the claim protocol for pull-request-gated Claude agents, as the Python package `sdlc_protocol`: the labels, the claim, the board, the protocol check, team mode's clerk, the push guard and the merge gate, with adapters for GitHub, a bare git repository and memory. README.md says what each module holds and who uses it; spec/PROTOCOL.md is the protocol in prose.

Four other repositories run a copy of this code, so a change here is a change there. ecosystem.json is the one record of who takes what: the template takes the whole package under tools/ (the board, the protocol check, team mode's clerk, the push guard), coordbench takes it under coordbench/vendor (its sdlc arm's gate and bare-git world), the plugin marketplace takes guard.py, and the private GitHub App takes claims.py and protocol_check.py; ECOSYSTEM.md is the map of it, generated by scripts/architecture.py. A pull request here runs the check named "check" and a job `downstream (<consumer>)` per consumer, which vendors the change into that consumer and runs its own check, so a change that breaks one is red before it merges. A merge that raises the version is a release, which .github/workflows/release.yml tags and publishes on the merge, or, in Developer mode (the repository variable SYMPHONY_DEVELOPER_MODE set to on), once the owner has approved it in the environment release; once it is published, .github/workflows/sync.yml vendors that release, from the commit that raised main to its version and never main's head, into every consumer and opens the pull request symphony-protocol/sync there, with the GitHub App's token, and each consumer's own check (with `vendoring.py verify`, which refuses a hand-edited copy) decides. What a release carries, and to whom, is that release's own package, ecosystem.json and scripts/vendor.py, so a change to any of them takes effect in the consumers with the next release and not before, with one exception. A rendered string (the board, the guard's refusals, the gate's answers, the record VENDORED) is part of the interface: change one only on purpose, and say so in the pull request. A consumer whose test pins it, or whose code calls a function that changes, goes first, by a pull request of its own that vendors the branch, which raises the version from the start, and answers the change; that consumer is the exception, since its copy has the change before the release is made, and keeps it if the owner rejects it in Developer mode. README.md, "A change a consumer must answer", has the order.

A release waits for the owner's approval, given in the browser in the environment release, only in Developer mode (the owner's decision of 2026-10-13, switched off on the owner's word of 2026-10-20 that no release waits on a hand step; README.md, "The owner's one-time setup for releases"), and the gate is code that runs from main. So a session never approves or rejects a deployment, never makes, moves or deletes a tag v<version>, and never publishes, edits or deletes a release, and never sets or changes the variable SYMPHONY_DEVELOPER_MODE, whatever tool or endpoint would let it, even acting under the owner's login. A session merges a pull request here once its checks are green, on the owner's standing permission of 2026-10-13, one that changes .github/workflows/, scripts/release.py or scripts/sync.py included; such a change takes effect the moment it merges, so its pull request says what it changes in the gate. README.md, Releases, says what the approval does not hold.

## Layout

- sdlc_protocol/: the package. The rules take what they need as arguments, the clock included; a rule that needs the outside world asks a World or a Client for it. The exceptions stay small and where they are: the guard asks git which branch is checked out in the clone a push runs in, the file system whether the directory a cd names is there, and HOME or the password database where a ~ leads, and board.write_if_changed writes STATE.md.
- sdlc_protocol/adapters/: the worlds and the REST client, the only modules that call GitHub or change a git repository. cli.py is the shell around them: it reads the environment, the event, stdin and the files it is named.
- spec/PROTOCOL.md: the protocol in prose, with no placeholders; it ships in the wheel as sdlc_protocol/spec/PROTOCOL.md.
- sdlc_protocol/vendoring.py: the record a copy carries and its check; it imports nothing from the package and nothing outside the standard library, since a consumer runs it as a script inside a copy that may hold only a few modules.
- ecosystem.json: the consumers, their copies and their checks; ECOSYSTEM.md: the map drawn from it and from the package's imports, which `python3 scripts/architecture.py` rewrites after a change to either.
- tests/: one test module per module, test_<module>.py, the scripts' included, with fixtures under tests/fixtures/.
- scripts/check.sh: the checks; scripts/vendor.py (and its wrapper vendor.sh): the copy into a consumer and its record; scripts/sync.py: the logic the sync and downstream jobs call; scripts/release.py: which versions the release workflow tags, where a tag stands, which both workflows check, and what its summary tells the owner before the approval; scripts/ecosystem.py: reading ecosystem.json and the imports, shared by the others.

## Checks

Run `bash scripts/check.sh` before opening or updating a pull request: it holds every file to ASCII with LF endings and a final newline, holds ECOSYSTEM.md to what scripts/architecture.py would write, then runs the whole suite. CI runs the same script on Python 3.12 as the job named "check". One module's tests run alone with `python3.12 -m unittest tests.test_<module> -v`. The version is `__version__` in sdlc_protocol/__init__.py and `version` in pyproject.toml, changed together; the tests fail when they differ.

## Writing

- Plain prose that says why, in docstrings, comments, commit messages, pull requests and documents alike. What the code does is read from the code.
- Short functions; names that read as English.
- No emoji in code, output or documents. ASCII and LF in every file, each ending with a newline: the package is vendored into repositories whose checks take nothing else.
- No new dependencies: Python 3.12 or later with its standard library, plain bash, and GitHub's own actions, pinned to a major tag. A proposal to add one is an issue first.
- Nothing refers to a file that does not exist.
- In conversation, put a fact worth keeping on its own line tagged `Decision:` or `Constraint:`, so a checkpoint keeps it word for word; the rest of a session is inferred and may be lost.
